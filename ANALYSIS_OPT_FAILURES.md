# OPT Generation Failures - Root Cause Analysis and Solutions

## Summary
The OPT (Operator Tree) generation fails for certain formulas due to three main issues in the `SemanticSymbol.parse_from_mathml()` method:

1. **Unhandled `<share>` elements** (8 occurrences)
2. **Missing `conditional` csymbol** (5 occurrences) 
3. **Missing `differential-d` csymbol** (1 occurrence)

## Issue 1: Unhandled Share Elements (href variants)

### Problem
The current code only handles:
```python
elif elem.tag == MathML.share:
    if elem.attrib["href"] == "#.cmml":
        # special handling
```

But the actual hrefs generated by latexmlmath are:
- `#Ex1.m1.sh1`
- `#Ex1.m1.sh2`
- `#Ex1.m1.1.sh1`

These represent references to previously parsed subexpressions (used in chained equations like `a = b = c`).

### Affected Formulas
- `R^2 = 2 = \frac{Q^2}{D^2}`
- `2^{1-1} = 2^1 / 2^1 = 2/2 = 1`
- `a^2 / a^3 = a^{-1} = 1/a`
- And 5 others with chained equalities

### Solution
The `<share>` element should return a "wildcard" placeholder rather than attempting to resolve the reference, since we're building a semantic representation that doesn't need to resolve cross-references. This is similar to how the code handles unknown identifiers.

## Issue 2: Missing "conditional" csymbol

### Problem
The `conditional` csymbol represents the divisibility operator `|` (e.g., `k|n` = "k divides n"), but it's not in the list of handled latexml csymbols.

### Affected Formulas
- `k|n`
- `p|(10^k-1)`
- `k|(p-1)`
- `P(X_n | X_1, X_2, \dots X_{n-1}) = P(X_n | X_{n-1})`

### MathML Example
```xml
<apply>
  <csymbol cd="latexml">conditional</csymbol>
  <ci>k</ci>
  <ci>n</ci>
</apply>
```

### Solution
Add `"conditional"` to the list of known latexml csymbols and map it to `"O!divides"` or similar.

## Issue 3: Missing "differential-d" csymbol

### Problem
The `differential-d` csymbol represents the differential operator `d` in integrals (e.g., `∫ f(x) dx`), but it's not in the list of handled csymbols.

### Affected Formula
- `\langle \, f, \, g \, \rangle = \int_a^b \ f(x)\overline{g(x)} \, dx`

### MathML Example
```xml
<csymbol cd="latexml">differential-d</csymbol>
```

### Solution
Add `"differential-d"` to the list of known latexml csymbols and map it appropriately.

## Key Insights
1. All formulas with chained equalities (multiple `=` signs) produce `<share>` elements
2. The issue is not with latexmlmath (which correctly generates MathML), but with the SemanticSymbol parser which doesn't handle all possible MathML constructs
3. Some missing csymbols are likely used in mathematical notation but not currently handled

## Recommended Fixes
### Fix 1: Handle Share Elements Gracefully
Replace the share element handling with code that returns a placeholder when href doesn't match the special case.

### Fix 2: Add Missing Csymbols
Add the following to the list of handled latexml csymbols in `SemanticSymbol.parse_from_mathml()`:
- `"conditional"` → `"O!divides"`
- `"differential-d"` → `"O!differential"`

### Fix 3: Improve Error Handling
Instead of raising `UnknownTagException` for unhandled csymbols, create a generic operator representation that preserves the symbol name for debugging.
